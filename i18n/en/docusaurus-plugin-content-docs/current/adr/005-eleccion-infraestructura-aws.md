# ADR 005: AWS Infrastructure Selection (Fargate vs. EC2)

## Context
As part of Task 5 of the ClínicaRed project, we were required to design and estimate the AWS cloud deployment infrastructure for the backend (Docker) and the PostgreSQL database, evaluating two main options to find the ideal balance between cost, performance, and administrative overhead.

- **Option A (Serverless Architecture):** Amazon ECS with AWS Fargate, Application Load Balancer (ALB), and Amazon RDS (`db.t3.micro`). Estimated cost: ~50.12 USD/month.
- **Option B (Traditional Architecture):** Amazon EC2 instance (`t3.small`) running containers manually and Amazon RDS (`db.t3.micro`). Estimated cost: ~33.02 USD/month.

## Decision
We decided to implement **Option A (ECS Fargate + ALB + RDS)**.

## Justification
Although Option B has a slightly lower monthly cost, Option A provides technical and operational advantages that justify the difference:

1. **Zero server management (Serverless):** With AWS Fargate, there is no need to patch, update, or manage the underlying operating system, allowing the development team to focus 100% on code and business logic.
2. **High availability and scalability:** Including an Application Load Balancer (ALB) enables efficient traffic distribution and automatic container scaling based on demand—a setup that would require significant effort to replicate and maintain manually on a standalone EC2 instance.
3. **Free Tier coverage:** A substantial portion of the costs associated with this architecture is currently offset by AWS Free Tier credits, keeping the actual financial impact minimal during initial testing and deployment.
